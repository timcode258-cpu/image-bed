## 一、原文摘录

以下三个完整段落来自用户提供的电子书，保留措辞。代码仅调整空白与缩进。补充解释在后面单独列出。

> 当程序调用CreateThread函数时，系统会为线程创建一个用来管理线程的数据结构，其中包含线程的一些信息，例如安全描述符、引用计数和退出码等，这个数据结构称为线程对象。线程对象属于内核对象，内核对象由操作系统管理，内核对象的数据结构只能由操作系统内核访问，应用程序不能在内存中定位这些数据结构并修改其内容。在调用一个创建内核对象的函数后，函数会返回一个句柄。该句柄标识了所创建的内核对象，可以由同一个进程中的任何线程使用，例如，对CreateThread函数来说，就是创建一个线程内核对象，返回一个线程句柄，线程句柄标识了所创建的线程对象。以后我们还会学习很多内核对象，例如进程对象、文件对象等都是内核对象。

> 接下来，系统会从进程的地址空间中为线程的栈分配内存空间并开始执行线程函数。栈空间用于存放线程执行时所需的函数参数和局部变量等，新线程在创建线程的进程环境中执行，因此它可以访问进程的所有句柄和其中的所有内存等，同一个进程中的多个线程也可以很容易地相互通信。

> 当线程结束时，线程的栈空间被释放，但是线程对象却不一定如此。在调用CreateThread函数后，线程对象的引用计数被设置为1，但是由于返回了一个线程句柄，引用计数又被加1，所以线程对象的引用计数为2。线程句柄可以由同一个进程中的任何线程使用，如果其他地方用不到该线程句柄，那么在调用CreateThread函数创建线程后，可以接着调用CloseHandle函数关闭线程句柄。关闭线程句柄会使线程对象的引用计数减1。这样一来当线程结束时，线程对象的引用计数再次减1，系统发现线程对象的引用计数为0，会立即销毁该线程对象。在调用CloseHandle函数关闭线程句柄后，对当前进程来说这个句柄就无效了，不可以再试图引用它，因此还应同时将这个线程句柄变量设为NULL，防止在其他函数调用中使用这个无效的线程句柄。例如：

```cpp
HANDLE hThread;
hThread = CreateThread(NULL, 0, ThreadProc, NULL, 0, NULL);
if (hThread != NULL)
{
    CloseHandle(hThread);
    hThread = NULL;
}
```

上面是原书的片段，未包含 ThreadProc 的定义等，不是完整可编译程序。

## 二、补充解释：每个名词对应什么

| 名词 | 含义 | 需要分清的事 |
|---|---|---|
| 线程的执行 | 运行指令、使用栈及执行状态的过程 | 是否还在执行代码 |
| 线程对象 | 系统维护的管理数据，记录状态、退出码等 | 是否仍需保留这些信息 |
| 有效句柄 | 程序通过 API 操作对象的入口 | 这份句柄是否仍能用于操作 |
| 句柄变量 | 例如 hThread，保存一个句柄值的变量 | 变量有数值不等于句柄有效 |

可以这样读它们的关系：**程序把句柄值交给 API，系统通过进程的句柄条目关联到线程对象。线程对象记录线程状态。** 句柄值不能当成线程对象的内存地址直接解引用。

线程结束后，程序可能仍要确认完成或读取退出码（线程结束时留下的结果数值），因此线程对象可以继续保留。有效句柄使程序能做这些操作。

### 原文中的“引用计数”如何理解

这里的引用可以理解为系统仍需保留对象的一项关联。原书的 1 → 2 → 1 → 0 是该段的简化说明，不应用来猜测运行中内核所有引用的精确数量。

**CloseHandle 成功后，传入的那份句柄即失效。** 线程对象仍保留，并不能说明被关闭的句柄还有效；关闭线程句柄也不会终止线程。

### 为什么还要 hThread = NULL

它让本地变量变成明确的空值，帮助防止误用。CloseHandle 成功才完成关闭；只给变量赋 NULL 不会关闭资源。

同样，写 `HANDLE another = hThread;` 只复制数值，不会自动获得另一份独立句柄。后面练习直接给定“两份独立有效句柄”的前提，本次不要求学习复制句柄 API。

## 三、把生命周期和等待连起来

以下是只有一份句柄 h 的教学情境：

| 发生的事 | 执行状态 | 句柄 h | 线程对象 |
|---|---|---|---|
| 创建成功 | 可以执行 | 有效 | 保留 |
| 线程函数返回 | 执行结束 | 仍有效 | 保留，仍可供查询或等待 |
| 随后成功关闭 h | 执行已结束 | 失效 | 无其他句柄或系统引用时可回收 |

另一种顺序是在线程仍在运行时关闭 h：h 会失效，线程仍可继续执行；此后不能使用这份旧句柄等待它。

### 等待到底在等什么

`WaitForSingleObject(h, timeout)` 可以等待线程对象。当线程结束时，线程对象进入“有信号”状态，表示相应等待条件已经满足。这里的“信号”不是发送窗口消息。

| 返回结果（等待对象是线程） | 含义 |
|---|---|
| WAIT_OBJECT_0 | 等待成功，确认线程已结束 |
| WAIT_TIMEOUT | 本次等待超时，不能据此宣布线程结束 |
| WAIT_FAILED | 等待失败，需要获取错误信息，不能当作完成 |

基本流程：**创建成功并保留句柄 → 等待并检查结果 → 按结果处理 → 不再需要时关闭句柄。**

超时后可能还需要继续等待；处理方式取决于程序目标。不能在另一个等待仍使用这份句柄时将其关闭。当前先按控制台情境理解；窗口线程的无限等待可能阻塞消息处理，后续再学如何配合消息循环。

依据：[CloseHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-closehandle)、[线程终止](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-thread)、[WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)。核对日期：2026-11-02。
